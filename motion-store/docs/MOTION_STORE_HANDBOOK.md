## 1. نظرة عامة وفكرة البيزنس

المحل بيشتري بضاعة مستعملة بالوزن، ويفرزها، ويبيعها بالكيلو أو بالقطعة. البرنامج بيتابع البضاعة من لحظة الشراء لحد البيع، وبيحسب تكلفة وربح **كل بالة**.

| المصطلح | المعنى |
| --- | --- |
| **بالة (Bale)** | كيس ملابس مختلطة بيتشرى بالوزن (40 / 45 / 50 كجم مثلاً). درجاتها: سوبر كريم، كريم، كريم في واحد، نمرة 1، نمرة 2، سحبة |
| **استوك (Stock)** | بضاعة جاية في شوال أو كرتونة، وزنها مش ثابت |
| **شراء مباشر (Direct)** | أصناف خاصة بتتشرى بالقطعة (مثلاً تيشرت زارا) |
| **الفرز (Sorting)** | تفتيح البالة وتقسيمها لدرجات: **عالي** (New Collection)، **وسط**، **تصفيات** (عيب بسيط)، **هالك** |
| **اللوت (Lot)** | مصدر بضاعة معيّن (مورد + بالة + موسم + وزن + تكلفة)، وبيفضل متتبّع لحد البيع |
| **الموسم** | صيفي / شتوي / ميكس / بدون |
| **الفئة** | حريمي / رجالي |
| **طن عادي / طن تشكيل** | نوع شحنة الشراء |

| الحاجة | الرقم |
| --- | --- |
| تطبيقات الباك إند (Domains) | 28 تطبيق |
| الشاشات | 18 صفحة + 15 مكوّن |
| روابط الـ API | حوالي 43 مجموعة (ViewSet) |
| ملف الـ API الرئيسي `views.py` | 3532 سطر |

## 2. طريقة البناء (التقنيات)

| الطبقة | التقنية |
| --- | --- |
| الباك إند | Django 5.1 + Django REST Framework 3.15 |
| الدخول | JWT (`djangorestframework-simplejwt`): التوكن صالح يوم، والتجديد 7 أيام بيتلف |
| توثيق الـ API | `drf-spectacular` (Swagger على `/api/docs/` و ReDoc على `/api/redoc/`) |
| الفلترة | `django-filter` + بحث وترتيب، وصفحات 50 سطر |
| القاعدة | SQLite للتشغيل المحلي (`USE_SQLITE=True` هو الافتراضي)، أو PostgreSQL 16 (Docker على بورت 5433) |
| الشاشات | React 18 + Vite 6 + Tailwind 3 + React Router 6 |
| مكتبات الشاشة | `axios` (الاتصال)، `lucide-react` (الأيقونات)، `exceljs` (تصدير Excel)، `html2pdf.js` (تصدير PDF) |
| اللغة | عربي (RTL) وإنجليزي، بزرار تبديل (`LanguageContext` + `i18n/translations.js`) |
| المنطقة الزمنية | `Africa/Cairo` |
| المعمارية | Modular Monolith: تطبيق واحد مقسّم لـ 28 قسم، وكل الحسابات في ملفات `services.py` |

**المبادئ اللي مايتنازلش عنها (من ملف المواصفات):**
- كل بيانات العميل (الاسم، الشعار، العنوان، الرقم الضريبي) قابلة للتعديل ومش مكتوبة في الكود.
- المخزون "دفتر حركات" هو مصدر الحقيقة (Ledger-based).
- محاسبة قيد مزدوج (المدين = الدائن دايماً).
- طريقة حساب التكلفة قابلة للاختيار (Configurable Costing Policy).
- كل حركة ليها أثر في سجل المراجعة (Audit).

## 4. التنصيب والتشغيل

### الطريقة السهلة على ويندوز
```
motion-store\RUN_MOTION_STORE.bat
```
السكريبت بيعمل:
1. يتأكد إن `backend\manage.py` و `frontend\package.json` موجودين.
2. لو الجهاز جديد: يعمل بيئة Python باسم الجهاز (`venv_<اسم الجهاز>`) وينزّل `requirements.txt`.
3. يشغّل `migrate` على SQLite.
4. يعمل الشركة الافتراضية `motion-main` ومستخدم `admin` بصلاحية ADMIN.
5. يفتح شاشتين: الباك إند على `0.0.0.0:8000`، والشاشات على `0.0.0.0:3001`، ويفتح المتصفح على `http://localhost:3001`.

### جهاز المحل
```powershell
powershell -ExecutionPolicy Bypass -File E:\MotionStore\Start-MotionStore.ps1
```
بيشغّل الباك إند (8000) والشاشات (3001) لو مش شغالين، وبيستنى لحد ما الاتنين يقوموا ويفتح المتصفح. الشاشتين السودا مكتوب عليهم "DO NOT CLOSE".

### يدوي
```bash
# الباك إند
cd motion-store/backend
python -m venv venv && source venv/bin/activate   # ويندوز: venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 0.0.0.0:8000

# الشاشات
cd motion-store/frontend
npm install
npm run dev        # على بورت 3001
npm run build      # نسخة للنشر في dist/
```
Vite بيحوّل `/api` و `/media` لـ `http://127.0.0.1:8000` لوحده.

### PostgreSQL بدل SQLite
```bash
docker compose up -d          # PostgreSQL 16 على بورت 5433
export USE_SQLITE=False DB_NAME=motion_store DB_USER=motion DB_PASSWORD=... DB_HOST=127.0.0.1 DB_PORT=5433
python manage.py migrate
```

### متغيرات البيئة (`.env`)
| المتغير | الافتراضي |
| --- | --- |
| `DJANGO_SECRET_KEY` | مفتاح تطوير (لازم يتغيّر في التشغيل الحقيقي) |

## 5. تعدد العملاء (Multi-Tenant)

```
Tenant (العميل)
  └── Companies (الشركات)
       └── Branches (الفروع)
            ├── Warehouses (المخازن والمحلات)
            └── POS Terminals (نقط البيع، وكل نقطة ليها درج كاشير)
```

- كل موديل بيورث `TenantAwareModel` (فيه `tenant` و `created_at` و `updated_at` و `id` من نوع UUID).
- `TenantMiddleware` بيحدد العميل من:
  1. الهيدر `X-Tenant-ID` (UUID)،
  2. أو `X-Tenant-Slug`،
  3. أو عميل المستخدم اللي داخل.
- الشاشة بتبعت `Authorization: Bearer <token>` و `X-Tenant-ID` مع كل طلب (`axiosClient.js`).
- `set_current_tenant()` بيخلي كل الاستعلامات تتفلتر بالعميل لوحدها.

## 7. الدورة الكاملة للبضاعة

```
المورد ──► فاتورة شراء (بالة / استوك / شراء مباشر) ──► لوت خام (RawLot) "مستني فرز"
   ──► الفرز: عالي / وسط / تصفيات / هالك ──► حساب التكلفة (سياسة التكلفة)
   ──► ترحيل للمخزون (StockItem + حركة SORT_IN) ──► نقل للمحل (TRANSFER_OUT / TRANSFER_IN)
   ──► التسعير (سعر الكيلو لكل درجة، أو سعر القطعة بكود) ──► البيع في وردية مفتوحة
   ──► خصم المخزون + تكلفة المبيعات + الفلوس في درج الكاشير + قيد محاسبي
   ──► (مرتجع ← البضاعة ترجع RETURN_IN، والفلوس ترجع أو قسيمة رصيد)
   ──► قفل الوردية (عجز/زيادة) ──► ترحيل الفلوس للخزنة أو لصاحب المحل
```

**أنواع حركات المخزون:** إدخال من الفرز (`SORT_IN`)، وبيع (`SALE`)، ومرتجع مبيعات (`RETURN_IN`)، ونقل صادر (`TRANSFER_OUT`)، ونقل وارد (`TRANSFER_IN`)، وتسوية بالزيادة (`ADJUSTMENT_PLUS`)، وتسوية بالنقص (`ADJUSTMENT_MINUS`)، وتخفيض قيمة (`WRITE_DOWN`).

### 8.1 تسجيل الدخول (`/login`)
- اسم المستخدم والباسورد، واختيار اللغة. بيجيب اسم العميل وشعاره من `tenants/public_info`.
- الدخول ← `POST /api/v1/auth/login/` (وبيانات المستخدم من `auth/me/`) ← بيحفظ `access_token` و `refresh_token` و `tenant_id`.
- لو التوكن خلص، `axiosClient` بيجدّده لوحده من `/auth/refresh/`.

### 8.2 الرئيسية (`/`)
تحية (صباح الخير / مساء الخير) باسم الدور، و**التارجت والرسالة** (رسالة من الإدارة + "عدّينا التارجت 🎉🔥"). الكروت:
- **ورديتي** (مقفولة ← "دوس هنا تفتح وردية")، وفواتيري النهاردة، ومتوسط فاتورتي، ومرتجعاتي النهاردة.
- أزرار سريعة: **بيع جديد** · **مرتجع** · **المعلقة والمؤجلة** · **الوردية**.
- طرق الدفع النهاردة، وأمانات ميعادها جه (متأخرة ⚠️ / النهاردة)، وعروض النهاردة، وآخر فواتيري.
- للمدير: بالات مستنية فرز، وأذون نقل النهاردة، وأصناف قربت تخلص، وآخر نتايج فرز، ومصروفات النهاردة، واللي علينا للموردين، وديون العملاء، وورديات فيها عجز (7 أيام)، ورسم المبيعات آخر 30 يوم، والأكثر مبيعاً النهاردة، و**محتاج انتباهك**.
- زرار **حفظ** للتارجت والرسالة (`home/settings`).

### 8.3 شاشة المبيعات (`/pos`) — أهم شاشة
**فوق:** الوردية (مفتوحة/مقفولة)، ونقطة البيع + **تغيير**. لو مفيش وردية: **فتح وردية جديدة** برصيد الافتتاح.

**إضافة صنف:**
- خانة **الكود** + **الكمية** + **الوزن (كجم)** + **إضافة (Enter)**.
- البيع **بالقطعة** أو **بالكيلو**. "اكتب الإجمالي والوزن أو العدد يتحسب لوحده".
- **الميزان:** زرار **+ بند ميزان** و **قفل الميزان** ("الميزان مفتوح: أي صنف هيدخل تحته") للبيع بالوزن المجمّع.
- قايمة **بضاعة المحل** فيها بحث بالاسم أو الكود، والصنف، والدرجة، وسعر الكيلو، والمتاح.

**الفاتورة:** الأصناف، وزرار **تفريغ (F3)**، و**تعليق** (فاتورة معلّقة)، و**المعلقة** (رجوع لفاتورة معلّقة).

**العميل:** تليفون أو كود العميل، واسمه، ولو جديد "هيتسجل مع الفاتورة"، وبيظهر اللي عليه. زرار **📝 رصيد قديم (ورقة)** لقسيمة رصيد قديمة.

**العروض والخصم:** قايمة العروض الشغالة، و**كوبون** + **تطبيق** + **شيل**، و**خصم يدوي**، و**توصيل**، و**رصيد سابق**، وملاحظات.

**الأونلاين:** صندوق لطلبات الأونلاين (اسم العميل والتليفون اختياري)، وليها تقفيل لوحدها في الوردية.

**الإجماليات:** الأصناف، وخصم العروض، والمطلوب.

**الدفع (F1):** طريقة دفع أو أكتر (**+ طريقة دفع تانية**)، وفاضل، والمستلم، والباقي للزبون. الآجل محتاج تليفون العميل. ← **تأكيد البيع**.

**بعد البيع:** "تم البيع" + **طباعة الإيصال** + **فاتورة جديدة**. الإيصال فيه رقم الفاتورة والعميل و"شكراً لزيارتكم".

**الرسايل:** "لازم تفتح وردية الأول"، "الفاتورة فاضية"، "الوزن أكبر من المتاح"، "الكود ده مش موجود".

**الفاتورة المؤجلة (أمانة):** بيعة بعربون والباقي بعدين. بعد كده يا تتحول لفاتورة (`convert`) يا تتلغي وترجع البضاعة (`cancel`).

### 8.4 فواتير المبيعات (`/invoices`)
- فلاتر: من تاريخ، وإلى تاريخ، والكاشير، ونقطة البيع، وطريقة الدفع ← **عرض**.
- كروت: عدد الفواتير، وإجمالي المبيعات، وإجمالي الخصومات، وحسب طريقة الدفع.
- تفاصيل الفاتورة (الأصناف، والخصم، والتوصيل، والرصيد السابق، والعروض، والكوبون) + **إعادة طباعة الإيصال**.
- **✏️ تعديل** و **🗑️ حذف** بباسورد المدير (`sales/{id}/replace`, `sales/{id}/delete_sale`, `sales/verify_manager`).
- **الترقيم:** إعداد أرقام الفواتير (`sales/numbering`).
- تصدير "تقرير فواتير المبيعات".

### 8.5 العملاء (`/customers`)
- كروت: عدد العملاء، وإجمالي مشترياتهم، وإجمالي اللي عليهم.
- بحث بالاسم أو التليفون أو الكود، و**عميل جديد** (الاسم، والتليفون، والعنوان، وملاحظات، وحد الدين اختياري) ← **حفظ العميل**.
- جدول: الكود، والفواتير، وإجمالي المشتريات، وآخر شراء، وأكتر حاجة بيشتريها، وعليه، وليه عندنا.
- ملف العميل: فواتيره بالأصناف، والتحصيلات، وزرار **تحصيل** (`customers/{id}/collect`).

### 8.6 الموردين (`/suppliers`)
- كروت: عدد الموردين، وإجمالي المشتريات، والمدفوع، وعليكم.
- **كشف الحساب:** التاريخ، والحركة (فاتورة/دفعة)، والمرجع، والرصيد.
- **دفع للمورد:** المبلغ، ولفاتورة معيّنة (اختياري)، وطريقة الدفع (ممكن "صاحب المحل من فلوسه الشخصية")، وملاحظات ← **تأكيد الدفع** (`suppliers/{id}/pay`).

### 8.7 المصروفات (`/expenses`)
- **إذن صرف جديد:** التاريخ، والبند (+ بند جديد)، والمبلغ، والخزنة ورصيدها، واتصرف لمين، والوصف ← **حفظ (محتاج باسورد المدير)**.
- كروت: إجمالي المصروفات، وعدد الأذونات، وأكبر البنود.
- فلاتر (التاريخ والحالة ساري/ملغي) وبحث.
- **إلغاء المصروف** بسبب ← الفلوس ترجع للخزنة (`expenses/{id}/cancel`).

### 8.8 التسعير والعروض (`/coding`)
3 تبويبات:
1. **التسعير (`PricingV2`)**
   - تكويد البنود: كود الصنف الفريد، واسم صنف البيع، وسعر القطعة، وسعر الكيلو ← **✨ تكويد وتسعير البنود المحددة**. "هوية البند الكاملة" (النوع، والصنف، والبراند، والدرجة، والموسم…)، والعدد والوزن المتاحين، والتكلفة الموزعة.
   - **سعر كيلو البالة** لكل درجة (عالي/وسط/تصفيات) ← **💾 حفظ وتحديث أسعار كيلو البالة**.
   - **سعر كيلو الاستوك** حسب الصنف والبراند والدرجة ← **💾 حفظ وتحديث سعر كيلو الاستوك**.
   - تنبيه تعارض لو بند مربوط بكود تاني ← **نعم، انقل البند للكود الجديد**.
2. **سجل التغيرات (`PriceLogV2`):** كل تغيير سعر بالتاريخ والمستخدم والقديم والجديد.
3. **العروض (`OffersV2`):** أنواع العروض:
   - خصم على الكمية (اشتري X قطع ← خصم %)، واشتري وخد، وخصم على الوزن، وشرايح وزن (1–3 / 3–5 / فوق 5 كجم)، وأي قطعة بسعر واحد، وقطعة معيّنة بسعر، ويوم الكيلو، والميزان بسعر ثابت، و**املى الكيس**، وكومبو، وخصم موجّه للبضاعة الراكدة، وخصم على الفاتورة، وهدية، وكوبون.
   - ينطبق على: الكل، أو التصنيف، أو الصنف، أو البراند، أو الدرجة، أو الموسم.
   - الوقت: من تاريخ لتاريخ، ومن ساعة لساعة، وأيام الأسبوع.
   - الكوبونات: توليد (`offers/{id}/generate_coupons`) وتحقق (`offers/validate_coupon`).

### 8.9 مرتجعات المبيعات (`/returns`)
- تبويبين: **مرتجع جديد** و **سجل المرتجعات**.
- البحث عن الفاتورة (`returns/invoice_lookup`)، وكل صنف بيبيّن: اتباع، واترجع قبل كده، وفاضل، وهيرجع.
- **ترد الفلوس إزاي:** نقدي، أو خصم من حساب العميل، أو **قسيمة رصيد** (Store Credit بكود).
- سبب المرتجع ← **تأكيد المرتجع**. والسيستم بيمنع ترجيع أكتر من اللي اتباع، وبيرد اللي اتدفع فعلاً بعد الخصم.
- **إعادة طباعة** إيصال المرتجع (بسعر كل صنف).

### 8.10 الفرز (`/sorting`)
- **قايمة الفرز:** المشتريات المستنية الفرز (رقم البالة/الفاتورة، والمورد، وتاريخ الشراء، والوزن الأصلي).
- لكل بالة: سطور بالدرجات **⭐ عالي** · **🔹 وسط** · **🏷️ تصفيات** · **🗑️ هالك (خسارة)**. كل سطر: اسم الصنف، والبراند (اختياري)، والعدد، والوزن ← **+ إضافة صنف**.
- **✨ مطابقة وترحيل للمخزون:** بيطابق الأوزان، ويحسب التكلفة، ويرحّل للمخزن (`sorting-orders/{id}/reconcile`, `calculate_costing`, `post_inventory` أو `raw-lots/{id}/sort_and_transfer`).

### 8.11 المخزون (`/inventory`)
- زراير فوق: **نقل بضاعة** و **إضافة مكان** (مخزن أو محل).
- تبويبات: **الأرصدة** · **سجل الحركات** · **أذون النقل**. وفلتر: المخازن / المحلات.
- **الأرصدة:** إجمالي الوزن، والقيمة بالتكلفة، والقيمة بسعر البيع، و"أصناف قربت تخلص (أقل من 10 كجم)". الجدول: الصنف، والدرجة، والمكان، والوزن، والقطع، وتكلفة الكيلو، وسعر البيع، والقيمة.
- **سجل الحركات:** فلاتر (التاريخ، والمكان، ونوع الحركة، والاتجاه داخل/خارج، والدرجة)، والرصيد بعد كل حركة، والمستند، وإجمالي الداخل والخارج والصافي.
- **إذن نقل بضاعة:** من، وإلى، والصنف، والوزن (والمتاح) ← **+ إضافة للإذن** ← **تأكيد النقل** (`transfers`).

### 8.12 المشتريات (`/purchasing`)
- 3 أنواع شراء: **بالة** · **استوك** · **شراء مباشر** (أصناف خاصة).
- **فاتورة شراء جديدة (`PurchaseInvoiceForm`):** المورد (+ مورد جديد)، والمخزن، ومصاريف النقل، ونوع الطن (عادي / تشكيل / **طن تشكيل جديد**)، وحريمي ولا رجالي، والموسم، ودرجة البالة، وعدد البالات، ونوع البراند (وان براند / ميكس براند)، والبراند (+ براند)، والتصنيف، والدرجة، والشراء بالوزن أو بالعدد ← **ضيف السطر** ← **حفظ الفاتورة** ("تم حفظ فاتورة الشراء وإرسالها للفرز").
- مصاريف النقل بتتوزّع على التكلفة.
- **إجراءات الفاتورة (`PurchaseInvoiceActions`):** 👁️ تفاصيل · ✏️ تعديل · ✖ إلغاء (بباسورد المدير وسبب) · افتح الفاتورة · قفل. الحالات: مسودة، مؤكدة، مستلمة، ملغية، وحالة الفرز (مستني فرز / بيتفرز / اتفرز).
- **كشف الموردين (`SupplierStatement`):** عدد الفواتير، وإجمالي الوزن، وإجمالي المشتريات، وآخر فاتورة.
- تقرير فواتير المشتريات.

### 8.13 الورديات (`/shifts`)
- **فتح وردية:** نقطة البيع، ورصيد الدرج دلوقتي، واللي اتعدّ في الدرج، وباسورد المدير ← **فتح الوردية** (`shifts/open_v2`).
- **الوردية الحالية:** الافتتاح، والمبيعات، وعدد الفواتير، وحسب طريقة الدفع، وحركات الدرج، والمتوقع في الدرج ← **تحديث**.
- **💸 ترحيل دلوقتي (من غير قفل الوردية)** لخزنة أو لصاحب المحل (`shifts/{id}/handover_now`).
- **🛒 تقفيل الأونلاين** منفصل (مش في الدرج): عدد الأوردرات، والإجمالي، وطرق الدفع، ومرتجعات أونلاين، وصافي الأونلاين.
- **↩️ مرتجعات حسب طريقة الرد**.
- **قفل الوردية:** اللي اتعدّ فعلاً ← الفرق (عجز/زيادة). العجز يتحسب: **على الكاشير (عهدة)** أو **على المحل (مصروف بباسورد المدير)**. والترحيل: **+ ترحيل** لخزنة أو لصاحب المحل، والباقي "هيفضل في الدرج للوردية الجاية" ← **تأكيد قفل الوردية** (`shifts/{id}/close_v2`).
- **سجل الورديات** (من/إلى) + **🖨️ طباعة** تقرير الوردية.

### 8.14 الخزينة (`/treasury`)
- أنواع الخزن: **درج كاشير** · **خزينة رئيسية** · **بنك / إلكتروني**.
- تبويبين: **الخزن** و **عهد الكاشيرية**. وإجمالي كل الخزن.
- **تحويل** بين خزنتين (`treasuries/transfer`)، و**إيداع / سحب** بسبب وباسورد المدير (`treasuries/adjust`).
- **كشف** أي خزنة بالتاريخ: رصيد أول المدة، والحركات، والرصيد (`treasuries/{id}/statement`). أنواع الحركات: مبيعات، ومرتجع، ومصروف، وإلغاء مصروف، وعربون مؤجلة، وتحصيل عميل، ودفع لمورد، وتظبيط افتتاح، وترحيل لصاحب المحل، وعجز على كاشير، وزيادة خزينة، وتسديد عهدة، وإيداع يدوي، وسحب يدوي.
- **عهد الكاشيرية:** الكاشير، والوردية، والحالة (مفتوحة/اتسددت) ← **تسديد** (تدخل خزنة) (`treasuries/settle_custody`).

### 8.15 التقارير (`/reports`)
شوف [القسم 14](#14-التقارير). فلتر الفترة + **عرض** + بحث في النتايج + تصدير (`ExportButtons`).

### 8.16 إدارة الموظفين (`/users`)
- **موظف جديد**، وبحث بالاسم أو التليفون أو الدور.
- الجدول: الاسم، واسم الدخول، والتليفون، والدور، ونقطة البيع، والفروع، وآخر دخول، والحالة (شغال/موقوف).
- **تعديل:** الاسم الأول والأخير، واسم الدخول، والتليفون، والدور، ونقطة البيع (أو أي نقطة)، والإيميل، والرقم السري (PIN) + **مسح الـ PIN**، والفروع المسموحة. وتغيير الباسورد (`users/{id}/change_password`).

### 8.17 إدارة الصلاحيات (`/permissions`)
لكل دور (كاشير، مدير، أمين مخزن، محاسب، فرّاز): علامات على الشاشات المسموحة، وعلامات على الأفعال الحساسة (الجدول في القسم 6). شارة "متعدّلة من الأدمن" أو "الافتراضي"، وزرار **رجوع للافتراضي** ← حفظ (`role-permissions`, `role-permissions/defaults`).

### 8.18 الإعدادات (`/settings`)
3 تبويبات:
1. **الشركة:**
   - **🧾 بيانات الشركة والإيصال (`ReceiptSettings`):** التليفون، والعنوان، والرقم الضريبي، والسجل التجاري، واللوجو، ومعاينة الإيصال ← **حفظ بيانات الشركة والإيصال** (`company-info/save`).
   - **سياسة التكلفة (`CostingSettings`):** 1) بالوزن · 2) بالقطعة · 3) بنسب الدرجات (عالي % + وسط % + تصفيات % + هالك % = 100%)، ومعالجة الهالك في الحسابات ("خسارة هالك الفرز") ← **💾 حفظ وتطبيق سياسة التكلفة** (`costing-config/current`).
   - **🏷️ أسعار العروض الجاهزة (`PromoPricesSettings`)** (`promo-prices/`).
   - **طرق الدفع والخزن ونقط البيع (`OperationsSettings`):** تبويبات طرق الدفع (نقدي / فيزا ومحفظة / آجل، وربطها بخزنة)، والخزن (رئيسية / درج / بنك)، ونقط البيع (الاسم، والكود، والفرع، والمخزن، و"هيتعمل درج كاشير مرتبط بيها لوحده").
2. **الفروع:** إضافة وتعديل الفروع.
3. **المخازن:** إضافة وتعديل المخازن والأماكن.

| --- | --- | --- |
| فاتورة شراء | من حـ/ 1010 مخزون البالات الخام إلى حـ/ 2010 الموردين، بإجمالي الفاتورة شامل النقل | `apps/accounting/auto_journals.py` ← `sync_purchase_journal` |

| الفرز والترحيل للمخزون | من حـ/ 1020 بضاعة تامة (تكلفة اللي دخل المخزن) + من حـ/ 5020 خسائر هالك الفرز (باقي تكلفة البالة) إلى حـ/ 1010 مخزون البالات الخام (تكلفة البالة كلها) | `post_sorting_journal` (بتتنادى من `post_sorting_to_inventory`) |
| البيع | من حـ/ 1030 النقدية (أو 1050 العملاء للآجل) إلى حـ/ 4010 المبيعات، ومن حـ/ 5010 تكلفة المبيعات إلى حـ/ 1020 | `process_pos_sale` |
| المرتجع | عكس قيد البيع | `process_sales_return*` |
| تسوية الجرد | العجز: من 5030 إلى 1020. الزيادة: من 1020 إلى 3010 | `stock_count/services.py` |
| المصروف | من حساب المصروف إلى 1030، والإلغاء عكسه | `_expense_journal` |
| دفع للمورد | من حـ/ 2010 الموردين إلى حـ/ 1030 النقدية. ولو اتدفع من فلوس صاحب المحل: إلى حـ/ 3010 | `post_supplier_payment_journal` |

**أمان قيود الشراء والفرز ودفع الموردين:**
- القيد بيتعمل في خطوة منفصلة (savepoint). لو فشل لأي سبب، الفاتورة أو الفرز أو الدفعة **بيتحفظوا عادي** زي الأول، والغلطة بتتسجل في اللوج.
- مفيش تغيير في جداول القاعدة (مفيش migrations).

**القيود القديمة (اللي اتعملت قبل الإضافة دي):**
```bash
cd motion-store/backend
python manage.py post_missing_journals            # معاينة بس، مابيكتبش حاجة
python manage.py post_missing_journals --apply    # بيعمل القيود الناقصة
```
بيدوّر على كل فاتورة شراء أو فرز أو دفعة لمورد من غير قيد، وبيعمله بتاريخ المستند نفسه. لو اتشغّل تاني مابيكررش حاجة.

> دفع المورد بيدخل على حساب النقدية 1030 حتى لو الخزنة بنك، زي البيع والمصروفات بالظبط، علشان الحسابات تفضل ماشية على نفس الطريقة.

## 16. ملاحظات وتحذيرات

- البرنامج كله في `motion-store/`، والنسخة القديمة اتمسحت.
- السكريبت `RUN_MOTION_STORE.bat` بيعمل مستخدم `admin` بباسورد بسيط مكتوب جوه السكريبت، و`docker-compose.yml` فيه باسورد تطوير. **لازم يتغيّروا** قبل أي تشغيل عند عميل، والمستودع عام.
- `DJANGO_DEBUG` افتراضياً `True` و `ALLOWED_HOSTS='*'`، ولازم يتظبطوا في التشغيل الحقيقي.
- التشغيل الحالي محلي على جهاز المحل (Django `runserver` + Vite dev). لسه مفيش إعداد نشر على سيرفر (gunicorn/nginx).
- ملف المواصفات (`MOTION_STORE_MASTER_SPEC.md`) فيه قرارات لسه ماتقفلتش: النسخ الاحتياطي، والفوترة للاشتراكات، وطريقة النشر.
- Motion POS خد من المشروع ده أفكار وقواعد شغل (الخزينة، والمصروفات، والتحويلات، والمشتريات، والتقارير) مش الكود.
